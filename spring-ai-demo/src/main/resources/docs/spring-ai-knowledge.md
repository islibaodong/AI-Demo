# Spring AI 产品知识库（仅用于 RAG 演示）

本文是第 6 课 RAG 的演示知识源。里面的内容不会在模型的预训练数据里，
所以「模型只能靠检索到本文才能答出来」——这正好验证 RAG 真的生效了。

## 创始人
Spring AI 项目的创始人是马克·波拉科维茨，他同时也是 Spring Data 的创始人。
该项目于 2024 年首次发布，旨在把 AI 能力以 Spring 原生方式带给 Java 开发者。

## 核心概念
Spring AI 最核心的对象是 ChatClient，它提供流式（fluent）的链式 API 来调用大语言模型。
支持 OpenAI、Azure OpenAI、Google Gemini、Amazon Bedrock 等多家供应商，API 保持一致，切换供应商几乎不改业务代码。

## 三大支柱
第一是模型（Model），即对话、文本向量化、图像生成等能力；
第二是工具调用（Function Calling），模型可以调用你注册的 Java 方法；
第三是 Prompt 与 Advisor，Advisor 可以在请求前后做增强，常见有记忆增强和 RAG 检索增强。

## 检索增强 RAG
RAG 的思路是：先把文档切块并向量化存进向量库；用户提问时，把问题向量化后做相似度检索，
取出最相关的几段当作"上下文"拼进提示词，再让模型基于这些资料回答。这样做可以让 LLM
回答预训练数据里没有的、或时效性很强的私有内容，同时大大减少幻觉。

## 适用场景
常见应用包括：企业知识库问答、客服机器人、文档摘要、自动化办公助手等，
凡是"让大模型基于你自己的资料回答"的需求，都是 RAG 的主场。
