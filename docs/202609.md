### 调研结论

**核心发现：Spring 官方已把这一批主题做成了现成工具箱。**
Spring AI 团队的 [Agentic Patterns 博客系列](https://spring.io/authors/tzolov/)（2026.01~04）+
社区项目 [`spring-ai-agent-utils`](https://github.com/spring-ai-community/spring-ai-agent-utils)
（`org.springaicommunity:spring-ai-agent-utils`，最新 0.12.0，Maven Central 可用）
把 Claude Code 的核心能力移植成了 Spring AI 工具，与本工程"记忆、技能"的需求严丝合缝：

| 模块 | 对应缺口 | 说明 |
|------|----------|------|
| `AutoMemoryTools` / `AutoMemoryToolsAdvisor` | **长期记忆** | 文件式跨会话记忆：`MEMORY.md` 索引 + 四类记忆文件（user/feedback/project/reference），沙箱目录，6 个工具操作；对照 Claude Code memory 与 [Claude API Memory Tool 规范](https://platform.claude.com/docs/en/agents-and-tools/tool-use/memory-tool)。与 ChatMemory 互补：窗口存"当前对话"，长期记忆存"值得永远保留的事实" |
| `SkillsTool` | **Agent 技能** | [Anthropic Agent Skills](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills) 开放标准的 Java 实现：SKILL.md + YAML frontmatter，**渐进披露三级加载**（元数据 → 正文 → 关联资源），按需扩展能力 |
| `TaskTools`（Task tool） | **多智能体编排** | [Part 4](https://spring.io/blog/2026/01/27/spring-ai-agentic-patterns-4-task-subagents/)：主代理 + Agent Registry + `agents/*.md` 配置的子代理，各子代理**独立上下文窗口**、可多模型路由、可并行；另有 `spring-ai-agent-utils-a2a` 模块支持 [A2A 协议](https://google.github.io/A2A/)远程子代理 |
| Session API（[Part 7](https://spring.io/blog/)，计划随 2.1） | **上下文工程/压缩** | 事件溯源的会话历史 + 轮次感知 compaction；行业共识（[Anthropic Compaction](https://docs.anthropic.com/en/docs/build-with-claude/compaction)）：~60-70% 窗口占用时主动触发、**先清工具结果再摘要**（实测省 52% 且准确率反升）、系统提示/任务陈述/近 5-7 轮保留原文、摘要用结构化 schema |
| `TodoWriteTool` / `AskUserQuestionTool` | 任务管理 / 澄清交互 | 小件，可并入相关课程顺带讲 |

**行业对照**（教学注释用）：记忆三层分类 working/session/long-term 与 CoALA 的
semantic/episodic/procedural（[LangGraph memory 文档](https://docs.langchain.com/oss/python/langgraph/memory)）；
三家记忆产品路线各异——[Mem0](https://mem0.ai/blog/state-of-ai-agent-memory-2026)（检索增强+自我改进）、
[Letta/MemGPT](https://www.letta.com/)（分层虚拟上下文，agent 自管记忆）、
Zep（时序知识图谱）。
